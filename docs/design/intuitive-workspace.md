# Focused website assessment

## Screen contract

The first screen has one job: start a real URL assessment. Use one labeled URL
input, one primary action, and a fill-only demo shortcut. A small CSS perspective
illustration adds depth without a downloaded model or renderer.

During assessment, show the current real stage and latest provider update. Keep
the timestamped activity log collapsed. Progress represents recorded states,
never an invented percentage. Failures retain observations already collected.

The report leads with the URL, finding count, PHP confidence, and AI suggestions.
Remediation rows reveal explanations and steps on demand; code requires a second
expansion. All findings, HTTP evidence, provider provenance, and coverage remain
available in disclosures. Evidence links open every containing disclosure and
move keyboard focus.

## Visual direction

Use the supplied Nimble reference's focused primary action and compact navigation
as structural inspiration, with PatchPilot's own identity. An ink sidebar anchors
a warm light workspace. Teal identifies actions, blue identifies live analysis,
and amber/rose communicate severity alongside explicit labels.

Use system fonts and a comfortable reading column. CSS depth and short transform
transitions provide motion; honor reduced motion. No external font, animation,
WebGL, or 3D dependencies.

## Acceptance

Verify empty, collecting, analyzing, completed, and failed states at 320, 768,
1024, and 1440 pixels. Preserve drafts, focus, and disclosures during polling.
Check keyboard operation, evidence navigation, inert model text, contrast, reduced
motion, console errors, and network/asset size. The default flow uses the real API
and Anthropic stream. UI test doubles remain test-only.
